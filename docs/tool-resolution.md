# External tool resolution

mAIestro Code shells out to a handful of external CLIs *itself* (distinct from the user-facing session it launches, which inherits the full ambient env). When the app is launched from the packaged bundle (`/Applications/mAIestro Code.app/…`) at login, macOS Launch Services gives it a **minimal `$PATH`** (`/usr/bin:/bin:/usr/sbin:/sbin`) with no shell profile sourced, so a bare `Command::new("claude")` (or `git`, or `code`) can fail to resolve or pick the wrong binary (e.g. the `/usr/bin/git` Xcode stub instead of a Homebrew git). `backend/src/tools.rs` centralizes resolution.

- **Tools that go through `tools`:** the agentic coding CLIs `claude`, `codex` and `agy` (Antigravity; AI drafting in `drafting::agent_text`, the Check Health probe, *and* the agent path baked into a worktree's generated VS Code startup task by `editor::write_vscode_files`), `git` (`gitops::git()` / `gitops::local_branch_exists()` — worktree add, branch checks), and the VS Code `code` CLI (`editor::open_vscode`). These are the ones invoked directly with the minimal PATH.
- **Tools that don't:** `open`, `osascript`, `lsof` are system binaries under `/usr/bin`, always on the minimal PATH; the login shell used for `post_spawn_commands` is invoked with `-l` so its children get a full PATH; and `gh` is **not used at all** (GitHub is the REST API — see "Talk to GitHub directly" in `CLAUDE.md`).
- **Login-shell PATH, recovered once.** At startup `tools::init()` (called from `setup()`) runs `$SHELL -l -c 'echo $PATH'` and caches the result — the user's *real* PATH (Homebrew, asdf/nvm shims, …). `enriched_path()` = that PATH followed by the process's own PATH (dedup, order-preserving), and every directly-spawned child is given it (`tools::command` / `tools::tokio_command`) so sub-tools the resolved binary calls resolve too. This one layer fixes every tool — and any added later — with no config.
- **`resolve_tool(name)` precedence:** an explicit override (`tool_paths` in global settings) is **authoritative** — once set it is the *only* source, so a pinned path can never silently resolve to a *different* binary. `resolve_tool` invokes it **verbatim** (even if missing, so a broken pin fails loudly with `No such file` rather than running a PATH binary); `find_tool` returns `Some` only when the pin exists, else `None` (a hard "not found" — **no** fall-through to auto-resolution). Only when **no** override is set do we auto-resolve: `which` on the enriched PATH → known install locations (`~/.claude/local/claude`, `~/.local/bin` — where `pip install --user` and the native installers put `claude` and `codex`, and Antigravity's install script puts `agy`, `/opt/homebrew/bin` (also the `antigravity-cli` cask's `agy`), `/usr/local/bin`, …) → (for `resolve_tool`) the bare name as a last resort. `stale_override(name)` returns the configured pin when it's set but missing (exactly the case `find_tool` returns `None` despite a pin), so the health check can name it. `resolved_status` reports the picked path + whether it exists, for the Settings UI. `tools_resolved` is the Tauri command backing the "Tool paths" status line.
- **Override config** lives in `~/.maiestro/settings.json`'s `tool_paths` (see `docs/settings.md`): a per-tool absolute path, empty = auto-resolve.

**An agentic coding CLI binary is resolved only when that agentic coding CLI is used.** `claude` is no longer assumed: a repo's AI calls, its spawned session's startup task, and its Check Health probe resolve the binary of the repo's effective agentic coding CLI (`repo_settings::effective_agent`, or the session record's `agent` for the startup task) and nothing else. On a machine with only `codex` installed, a Codex repo never invokes `claude` or `agy`, and the same holds for each agentic coding CLI. Every agentic coding CLI is still listed in `tools_resolved`, so the General panel's "Tool paths" block shows `claude`, `codex` and `agy`, and any can be pinned.

**Antigravity's binary isn't its setting value.** The `agent` value is `antigravity`, but the CLI (and its `tool_paths` key) is `agy`. Always resolve an agent through `Agent::tool()`, never `Agent::as_str()`.
